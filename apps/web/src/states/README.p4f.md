# states: offline shell, exports, coverage, resilience, security headers (round 6)

All of this is reached through `handleRequest()` in `app.ts`.

- **Offline.** `/sw.js` is generated by `buildServiceWorker()` from a validated config. Navigations go network-first with a timeout, then fall back to the last copy of that page, then to the localised offline page (`/en/offline`, `/fr/hors-ligne`). POST and cross-origin requests, error responses and `no-store` responses are never intercepted or cached. `serviceWorker.test.ts` runs the generated script against fake browser APIs. `/register-sw.js` registers it, so no inline script is needed. `/manifest.webmanifest` follows the visitor's language. The manifest declares no icons because the package ships no images; a deployment adds its own.
- **Exports.** `?format=text` on a place gives a plain-text summary; `?format=csv` on the saved page downloads one row per place and feature with status, source, licence, retrieval date and source URL. UNKNOWN stays `unknown`. CSV cells that begin with `=`, `+`, `-`, `@`, tab or CR are prefixed with `'` so a spreadsheet will not run them as formulas.
- **Coverage page** (`/en/coverage`, `/fr/couverture`). Counts of yes, no, partly and UNKNOWN for every feature, located and unlocated places, places with details older than a year, and records dropped for being incomplete.
- **Map.** A GET form takes a latitude and longitude (decimal point or comma). The point is used only for sorting; it is not stored, and the browser's geolocation is disabled by the permissions policy.
- **Resilience.** `safeLoad()` adds a timeout (default 8 s) and validates what the loader returns. Malformed records are dropped and counted; a thrown error becomes an error page; `handleRequest` never throws and its 500 page reveals nothing about the cause. Settings and the offline page do not wait for data.
- **Security headers.** Every response carries a content security policy that allows same-origin resources only, so third-party scripts, tiles or fonts cannot load. `style-src` allows inline styles because the renderers put the palette-checked colours in `style` attributes; scripts get no such allowance. `auditHeaders()` fails on a missing or weakened policy, wildcard or third-party sources, `unsafe-inline` or `unsafe-eval` in scripts, missing `nosniff`, referrer or permissions policy, or a missing charset.
- **Audit.** `auditHtml` now also fails on inline scripts, scripts or other resources (images, stylesheets, frames, media, form targets) loaded from another origin.
